When summarizing pierside / wet-berth NDI technology (Edify-style magnetic crawler with pulsed eddy current array and ultrasonic, or any similar in-service hull-thickness inspection capability) for a Navy / SRF-JRMC reader, frame the operational use as follows:

The crawler is deployed during a non-docking maintenance period, while the ship is pierside. The output is a hull-thickness inspection report. The shipyard maintenance planners use that report to plan scope for the next docking availability — well ahead of the ship actually docking. The value is not last-minute inspection before docking; the value is lead time on docking-availability scope planning informed by hard data rather than estimates. That lead time is what prevents the post-docking scope-creep discoveries that drive the overruns CBO publication 61940 documents.

**Why:** Operator (J. Anguiano, SRF-JRMC waterfront experience) explained the actual workflow on 2026-06-04 after I had written it as a near-docking-event inspection. His words: "We would find these problems via NDI well ahead of putting a ship in the dock. ... The Robot Crawler would be used in a maintenance period prior to a docking period. While the ship is pierside, we would run that, we would get a report, we would understand what to plan for." This is operator-direct from someone who knows how the Yokosuka waterfront actually runs an availability cycle.

**How to apply:**

1. **Default framing for in-service hull NDI capability:** "deployed during a non-docking maintenance period (ship pierside), generates an inspection report, feeds scope planning for the next docking availability."

2. **Don't write framings like "inspect right before docking" or "pre-docking inspection that lets you know scope as the ship docks down."** Those imply a deploy-deploy-deploy-go-to-dock workflow that doesn't reflect how Navy maintenance planning actually runs.

3. **The lead-time framing is the right value pitch:** weeks or months between the pierside inspection and the docking availability. That's enough time to size, fund, schedule, and procure for the work.

4. **Cross-reference for BDR:** the same lead-time pattern applies to battle-damage-assessment workflows — assess early so the repair planning has runway. The Edify pierside-NDI use case is structurally analogous to BDR forward-team damage-assessment workflows.

5. **The CBO report ([publication 61940](https://www.cbo.gov/publication/61940), "Maintenance Delays for Conventional Navy Ships," December 2025)** is the data foundation: 14 years of Navy schedule data, DDG-51 overhauls running 20%–150% over the 2012 class plan, 9 years projected out of the fleet for maintenance vs. ~4 planned. Pierside in-service NDI capability is one of the technology adoption paths under NDAA §345 that could compress that pattern.
