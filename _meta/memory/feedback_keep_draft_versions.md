The operator likes keeping **every** draft version of an artifact (capture brief, RFI
response, exec summary: v0.1, v0.2, v0.3, …) in the opportunity folder. They value
being able to go back and forth and see how the work changed and grew over time.

**Why:** the version lineage is the value — the operator reads the progression, not
just the latest draft.

**How to apply:** when iterating a draft, create a NEW version file; do not delete or
overwrite superseded versions, and do not offer to "prune for clutter" (offered once
on MDES-PSNS, explicitly declined). Git history is a backup, not a substitute — the
operator wants the versions visible in the vault itself. Consistent with the
build_brief lineage convention.
